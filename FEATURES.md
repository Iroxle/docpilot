# DocPilot 1.0: Features and limitations

The interface consists of a title bar with the tabs, the menu (☰) and a search field for all tools and commands, a tools pane on the left, quick tools on the side, a sidebar on the right and page controls at the bottom right.

## Fully implemented and tested in the app

| Area | Features |
|---|---|
| Interface | Title bar with the tabs, the menu (☰, also Alt or F10) and a search field for all tools and commands. Home page: drop a PDF on the large area or open one, recent files as pictures of their first page (full path as tooltip; right-click: open, show in Explorer, remove from list), tiles of the main tools. Tools pane: every tool group has a color of its own, a search field filters groups and tools while typing, the pane slides in and out (as does the sidebar on the right). Empty panels say what to do. |
| View | Tabs, zoom, single page, continuous, two-up, rotate view, reading mode, full screen, rulers, grid, hand tool, marquee zoom, snapshot, read out loud |
| Find | Search with result highlighting, advanced search with result list, whole words, match case |
| Find and replace | In the find bar (Ctrl+F, show the "Replace with" row on the left, or Ctrl+Shift+H). "Replace" replaces the highlighted result and jumps to the next one, "Replace all" replaces in the whole document, both with "Whole word" and "Match case". Text is really replaced in the page content, the same way as in "Edit PDF": font, size and color stay. If a line in a running-text paragraph becomes too long as a result, the paragraph reflows; single lines (table, address, heading) stay single lines. It also works for recognized text in scans: the old letters are removed from the image. "Replace all" states the number of results first, is a single step for "Undo", and reports afterwards how many positions were replaced and which were not (with page and reason). The old page content is removed from the file, not just hidden. If the replacement text contains the search term, no position is replaced twice when clicking through. |
| Comments | Highlight, underline, strikethrough, squiggly, replace text, insert text, sticky note, text box, callout, pencil, eraser, rectangle, ellipse, line, arrow, polygon, polyline, cloud, stamp, custom stamps, replies, status, comment list, XFDF, flatten. Everything is saved as a real PDF annotation. |
| Edit | Change text, move, resize and delete images, add text and images, links, crop, page size, header & footer, page numbers, watermark, background, Bates numbering, page labels |
| Header, footer, watermark, background | Each is a mark of its own in the page (a tagged artifact). When a document already has one, the tool offers Update (the dialog opens with the settings it was made with and replaces it on all pages), Remove, or Add another; removing leaves the page content as it was. Page numbers are a header or footer. Watermarks can lie behind the page content; backgrounds always do. Bates numbers and printer marks work the same way. |
| Pages | Move, rotate, delete, duplicate, insert, replace, extract, split, combine, reverse (all or chosen pages; the other pages stay in place) |
| Page boxes | "Set page boxes" (Print production): crop, bleed, trim and art box from margins measured inward from the media box, or back to their default; the current boxes of the page are listed. A box is clipped to the media box. |
| Combine, insert, extract, split | Bookmarks, links within the document (also to named destinations, which become explicit ones), form fields, layers with their default visibility, attachments and page labels come along. Links to pages that are not copied are dropped instead of pointing nowhere. Combining gives every file a bookmark at its first page with the file's own bookmarks below it; "Insert pages from file" adds such a bookmark among the existing ones. Form fields whose names are already taken are renamed ("Name-1") so they stay separate, and the app says which. Fonts, images and colour profiles that several files share are stored once. Duplicated pages are more widgets of the same form fields (one value on both pages). |
| Forms | Fill in, create all field types (also date fields, image fields and tables of text fields), detect fields automatically, required, read-only, export/import data (XFDF, FDF, XML, CSV, tab-delimited text, JSON), reset, flatten |
| Formats and calculations | Field properties: number (decimals, separator style such as 1'234.56, negative numbers in parentheses, currency before or after), percentage, date (e.g. dd/mm/yyyy), time, special (zip code, phone, social security number) and custom masks; value range; calculation as sum, product, average, minimum or maximum of fields (a group name counts all fields below it) or as an expression ("Quantity * Price + Shipping"). They are written as the standard scripts other PDF programs run, and DocPilot runs them itself while JavaScript stays blocked: values are formatted when a field is left, entries that do not fit the format or the range are refused with a message, and calculated fields update in the calculation order. Calculation order dialog (with a warning when a field reads one calculated after it), tab order by rows, columns or structure. Image fields: a click while filling in chooses the picture. |
| Detect form fields automatically | Under "Prepare form", "Detect fields automatically" looks for places to fill in on the selected pages: lines and underscores (text fields), empty boxes and table cells (text fields, tall boxes multiline), small squares (check boxes), circles (radio buttons, side by side or below each other as one choice) and signature lines (signature fields). The field name comes from the label to the left or above, for check boxes and options from the text to the right, for lines also from the small line below ("Place, date"); in tables from the column header. Names are unique ("Day", "Day 2"). The detected fields first appear as a preview on the page; a click deselects or selects a field, they are only created after you confirm, all together as one step for "Undo". Where a field already exists, none is suggested. Separators, underlined text, frames around text and bullet points do not become fields. It also works for scanned forms: lines and boxes are looked for in the image, the names come from the recognized text. |
| Fill and sign | Fill in and sign, line, drawn/typed/image signature, initials, create digital ID, sign digitally, certify (visible or invisible, with the allowed changes: none, form filling and signing, or also comments), validate signatures |
| Saving | Save writes only the changes at the end of the file (incremental update): the original bytes stay as they are. Signed documents are always saved this way, so their signatures stay valid when they are filled in, commented or signed again. Save as writes a new, complete file; after redacting, compressing, sanitizing or changing the protection, the whole file is written again so that removed content really leaves it. The Signatures panel shows for every signature whether the document changed after it, what (form fill, comments, signatures, document information, page content) and whether that is permitted. |
| PDF/A | "Save as PDF/A" (PDF/A-2b or PDF/A-3b) checks the rules that can be decided from the document's objects: header and file identifier, encryption, XMP identification and title, output intent for device colours (RGB and CMYK), embedded fonts, LZW and external streams, image interpolation, alternates and OPI, PostScript, actions and scripts, annotation types, flags and appearances, NeedAppearances and XFA, embedded files. It fixes what can be fixed without changing the pages and lists what remains before saving. "Check PDF/A compliance" lists the problems for both levels without changing anything. |
| Protect | Password (AES-256), permissions, remove security, sanitize document, redact with search for text, IBAN, email, Swiss AHV numbers, phone numbers |
| Redact | Marks stay editable until "Apply redactions". Then the glyphs under the marks are cut out of the page content (the rest of each line keeps its place), invisible text from text recognition too; images that are fully covered are removed, partly covered ones get the covered pixels cleared in a copy; inline images under a mark are removed; graphics that are fully covered are removed and partly covered ones are clipped; form XObjects under a mark are rewritten as new objects, so other pages that use them keep theirs. Comments, links and form fields over a mark are removed. The originals of changed images and forms leave the file. Document information, XMP metadata and tag texts that repeat the removed words are removed; bookmark titles that repeat them are reported. Every page is checked again afterwards (by DocPilot's reader and by PDF.js); if anything is still under a mark, nothing is changed. Redaction properties: box colour or no box, overlay text, text colour, size (or fit), alignment, repeated text. |
| Reduce file size | "Reduce file size" with Standard (images to 150 ppi above 225 ppi, JPEG medium), Mobile (96 ppi, JPEG high) or High quality (300 ppi). The resolution is measured where the pages draw each image (the smallest use counts, also inside form XObjects); images that comments or patterns also draw stay as they are. Colour and greyscale images are resampled (Catmull-Rom) and stored as JPEG or Flate, a soft mask together with its image; black-and-white images are averaged down (300 ppi above 450 ppi) and stored as CCITT Group 4 or 1-bit Flate. A new image only replaces the old one if it is smaller. Clean-up: page thumbnails, alternate images, images and forms that no page draws, links to pages that do not exist; uncompressed data is compressed, LZW data and outer ASCII85/ASCIIHex layers become Flate. "Advanced optimization" offers every setting, also discarding tags, form actions, print settings, links to other documents and an embedded search index; the last choice is remembered. |
| Convert | Word, Excel, PowerPoint, PNG, JPEG, HTML, RTF, TXT, Markdown (headings from the font size, bold and italic, lists, tables as pipe tables). Export all images: every image once, JPEG unchanged, other images as PNG with transparency (soft masks, masks and colour keys), JPEG 2000 as .jp2; images that cannot be decoded are listed. PDF from image, text, HTML, clipboard, Office files; several files as separate PDFs in a folder |
| Print | Pages per sheet (2, 4, 6, 9, 16; horizontal or vertical order, also reversed; page borders; pages turned to fit the cells), booklet (saddle stitch, padded to a multiple of four, both sides or front or back only, binding left or right; two-sided printing on the short edge), fit, actual size, shrink oversized pages, custom scale, paper size (A4, A3, A5, Letter, Legal), reverse order, odd/even pages, document and comments, document only, or form fields only |
| Print production | Preflight report, PDF/A check, crop, page boxes. Convert to grayscale: colour operators in the page content, in the forms it draws and (optionally) in comments and form fields become gray by their brightness (pure black stays black); RGB and CMYK images become gray images. Fix hairlines: lines thinner than a limit on the page (after any scaling) or without a width get a new width; forms drawn at a scale are fixed as a copy. Printer marks: trim and bleed marks, registration targets in registration colour, CMYK colour bars, page information (file, page, date); the page grows by at least 36 pt when the marks would not fit, the trim box keeps the old page area; can be updated or removed. |
| Tables in export | Tables arrive in Word, Excel and PowerPoint ("editable" mode) as real tables. They are detected from the drawn lines (grid with rows, columns and merged cells) and from the alignment of the text (tables without lines: columns are separated by continuous white space, at least two rows). Word: rows, columns, merged cells, column widths and alignment (numbers right-aligned, headers across several columns centered); tables without lines stay without borders. Excel: one sheet per page, every cell in its own cell, merged cells merged; numbers and dates are real values with a matching format (1'250.00, 1 250,50, CHF 12.50, 12.-, 7.7 %, -12.50, 12.11.2026). Text outside the tables is kept line by line; "Total" and the amount below a table go into its columns. Also for scanned tables: lines from the image, text from text recognition. Verified: Word, Excel and PowerPoint open the generated files. |
| Fonts | Like Word: all installed fonts (for all users and for the current user only) and the Office cloud fonts such as Aptos that Office has downloaded. Font list with theme fonts, recently used fonts and all fonts, each shown in its own typeface, type-ahead search. New text starts in Word's default font and size (from Word's Normal.dotm template, otherwise Aptos 11). If a font has no bold or italic style, it is synthesized like in Word. Fonts whose license forbids embedding are grayed out. Comments deliberately keep the standard font, without font choice. |
| Scans and text recognition | Scanned documents are detected when opened (offer "Recognize text", automatically, or never, in Preferences). PDFs created from an image, the scanner, the clipboard or a dropped image (e.g. a photographed invoice) are read immediately. Images with an A4 aspect ratio are set to A4. Recognized text is searchable and copyable, including text in images on normal pages. Under "Edit PDF" it can be changed, moved or deleted: the old letters are really removed from the image (table lines and colored backgrounds remain), and the new text appears in the same font, size and color. Everything runs offline on the PC. |
| Scanned invoices and tables | Table lines and separators (solid, dashed, dotted) are removed from the image before recognition, as is scanner noise; this way even the line directly below a rule is read correctly. Every table row, every number and every address line is its own block and stays separate when edited; only wrapped running text becomes a paragraph that reflows when changed. Numbers in right-aligned columns stay right-aligned when changed. Text of the same size gets the same size. Whatever recognition reads into logos and graphics is discarded. Scans that the scanner split into strips or tiles are treated as a whole page: the pieces are locked (no frames, no accidental moving), and when editing, the old letters are removed across strip boundaries too. Under "Scan & OCR", text that was already recognized can be recognized again, e.g. for scans from an older version. |
| Skewed scans | Before text recognition, the rotation angle of each page is determined (accurate to 0.15 degrees in the test, up to 12 degrees). A skewed page is straightened for reading. The recognized text is then placed over the unchanged image with the rotation of the lines: searching, highlighting, copying and editing in the image are right even at the end of a line. "Straighten page" under "Scan & OCR" rotates the image of the page itself straight: detected angle, preview with guide lines, angle adjustable by hand, for one or several pages. Recognized text is read again afterwards; everything together is one step for "Undo". Preference "Straighten skewed scans automatically when recognizing text" under Scan & OCR (default: off; the image then stays as it is, and the app points out clearly skewed pages after recognition). Pages that are straight (below 0.3 degrees), pages without recognizable lines and normal PDFs that are not scans stay unchanged. |
| Paste screenshots | Ctrl+V pastes an image from the clipboard (e.g. a screenshot taken with Win+Shift+S) in the middle of the visible page, at its original size or scaled down to fit the page. The text in it is recognized immediately. Without an open document, a new PDF is created. In input fields, Ctrl+V stays normal paste. Under "Edit PDF", the pasted screenshot behaves like an object: a click anywhere on it (including its text) selects the whole image, dragging moves it together with its recognized text, the corner resizes it, Del deletes it including its text. Double-clicking the text edits it. |
| Keep writing in screenshots | If recognized text in a pasted screenshot gets longer (new line with Enter, longer sentence), the editor makes room in the image: everything below moves down together with its recognized text and the image gets taller, like in Word. New text appears in the font, size and color of the image, including light text on a dark background. Enter at the end without further text does not add an empty line. |
| Screenshot recognition | Also light text on a dark background (dark mode). Bullets (•, ◦, ▪) and numbers are kept as separate characters, each item is its own paragraph, wrapped lines stay aligned. Bold lines are detected. The font of the image (e.g. Segoe UI, Arial, Calibri, Verdana, Times New Roman, Georgia) is detected from the word widths and used when editing. Multi-line paragraphs reflow like in Word when edited. The recognition resolution adapts to the image. Common misreadings are checked against the glyph shapes and corrected (± instead of +, umlauts, period and comma, i instead of 1). |
| Appearance | Under Preferences > General: Light (default), Dark or Same as Windows. In the dark appearance, the title bar with the tabs and the window buttons, the toolbar, tools pane, sidebars, page controls, find bar, dialogs, input fields, font picker, messages, home page and "All tools" are dark and readable (measured in the test: contrast of text to background at least 4.5 to 1, for icons 3 to 1). The PDF pages stay white like paper; only the background around the pages becomes dark. Form fields and input on the page, page thumbnails and the signature pad stay light too. The change takes effect immediately, without a restart. "Same as Windows" follows the Windows mode, even if it changes while the program is running. If the choice is Light, the program stays light even when Windows is dark: nothing changes for existing users. |
| Preferences | Structured by category (Ctrl+K): General, Documents, Units & Guides, Forms, Identity, Convert to PDF, JavaScript, Comment, Scan & OCR, Page Display, Read Out Loud, Find, Trust Manager (links, attachments) |
| Security | JavaScript in PDFs and macros during conversion are blocked. Attachments are never run. Links only open web pages and email, after confirmation. HTML is converted without JavaScript and without internet access. The program is hardened against misuse as a scripting tool (Electron fuses). |
| Measure | Distance, perimeter, area with a scale. The tools snap to the drawn lines of the page within 8 screen pixels: end points first, then middles, crossings and the nearest point on a line (also inside forms); a marker shows the snap. "Snap to lines and points" turns it off and on. "Export measurements (CSV)" writes page, type, value, unit, label and author for a spreadsheet. |
| Working with documents | Reopen closed tab (Ctrl+Shift+T), Show in Explorer (File menu, right-click on a tab), close other tabs, search commands (Ctrl+Shift+P: every tool and menu command by name, arrow keys and Enter), search bookmarks (matching titles with the bookmarks above them), thumbnail size (slider in the thumbnails panel), fonts in Document properties (type, embedded, subset). Recovery after a crash: documents with unsaved changes are copied to the app's data folder every 1 to 10 minutes (Preferences > Documents, default 2) and offered for recovery at the next start if DocPilot was not closed properly. |
| Accessibility | "Automatically tag document": every text object becomes a paragraph or a heading (level 1 from 1.6 times the body size, level 2 from 1.25 times or a short bold line), images become figures, lines, fills, shadings and forms outside text are marked as decoration (artifacts); headers, footers and other page marks stay artifacts; form fields become Form tags described by their tooltip, links Link tags; pages with annotations get the tab order of the tags; the document is marked as tagged. Tags panel: the tag tree with page, type and alternate text; a click goes to the page, "Tag properties" changes the type and the alternate text. "Alternate text for images": every figure with a picture of it. "Tag form fields and links" for fields added later. "Accessibility check": 32 rules in the groups document, page content, forms, alternate text, tables, lists and headings, each passed, failed, not applicable or to check manually (reading order, colour contrast, flicker, timed responses, navigation links), with a fix button for tagging, title and language, tab order, form fields, alternate text and text recognition. "Set title and language" also makes the window show the title. |
| Batch OCR and scan clean-up | "Recognize text in several files": PDFs and images, each saved as a searchable PDF ("_OCR") in a chosen folder. "Enhance scanned pages": the lighting is evened out (paper white, shadows and darker edges gone), the contrast raised and specks removed, or the scan becomes black and white (local threshold, 1-bit); the images are changed where they are, so recognized text, comments and form fields stay; pages that are not scans are left alone. "Straighten photo (perspective)": the sheet in a phone photo is found by its edges, the corners can be moved on a preview, and the area inside becomes the page, upright and rectangular. "Review recognized text": the words recognized since the document was opened, below 70 % or 90 % certainty or all, each with its picture and certainty (colour and number); corrections replace the words in the text layer, as one step for "Undo". |
| Action wizard | Steps: recognize text, enhance scanned pages, reduce file size, remove hidden information, flatten comments, flatten form fields, add watermark, header or footer (with placeholders), set document title, convert to grayscale, fix hairlines, automatically tag, convert to PDF/A-2b. Built-in actions: Prepare for distribution, Optimize scanned documents, Add page numbers, Mark as confidential, Make accessible, Archive as PDF/A. Steps can be added, moved and removed; own actions are saved. The results are saved under the same names in a chosen folder ("_processed" in the files' own folder); a file whose step fails is not saved, and the report says why. The originals stay unchanged. |
| XFA forms | When an XFA form is opened, DocPilot offers to convert it. Static XFA forms keep their pages and fields and only lose the XFA part. Dynamic forms are laid out from their template: page size and content area, positioned, top-to-bottom, left-to-right and table layouts, margins, captions (left, top, right, bottom, reserve), fonts and alignment, hidden content, page breaks and content that continues on new pages, repeating sections (one per data record). Text, lines and boxes become page content; text fields (also multiline), number and date fields, check boxes, radio button groups, dropdowns, lists, buttons and signature places become form fields with their values from the form's data and their tooltips. |
| More | OCR (German, English, French, Italian), compress, compare, bookmarks, attachments, layers, properties, open options, save document JavaScript |

## Limited

| Feature | Limitation |
|---|---|
| Edit text | Changed text is set again with the matching installed font (not with the embedded original font); a paragraph that is only moved, and the unchanged parts of a paragraph with columns or mixed formats, keep their original font and glyphs. If the PDF's font is not installed, a similar one is chosen (the input field then shows that font). In tables, label/value columns and paragraphs with mixed formats, every part keeps its size, weight and place, already in the input field. Lines do not wrap while typing; a line that would run over the page edge is set as a whole, wrapped, in one format. Text in nested objects is covered instead of removed. Reflow across columns is missing. |
| Find and replace | As with "Edit text", the affected paragraph is set again with the matching installed font; justified text becomes left-aligned. Not replaced (and reported): rotated text and results that span several paragraphs or table cells. Text in comments, form fields, bookmarks and document properties is not searched. Text in nested objects is covered instead of removed (the app reports this). If a paragraph becomes one line longer, the text below does not move down (except in pasted screenshots). If the text becomes shorter, the line breaks stay as they are. On pages that have already been edited, the order when clicking through can differ from the reading order. No search patterns (regular expressions). |
| Fonts | Office cloud fonts can only be chosen once Office has downloaded them to the PC (Word downloads them on demand). Characters that a font does not contain appear as "?" (Word switches fonts automatically for these). Very large fonts (e.g. for Chinese) are embedded in full and make the PDF larger. |
| Edit recognized text | The font is chosen from the common Windows fonts; a rare font in the image is replaced with the closest match (it can be changed freely). Changed text is drawn more smoothly than the screen font of a screenshot. On photos, gradients or patterned backgrounds, the edited spot may be slightly visible. Handwriting is not recognized. Text stored in the PDF as vector graphics (not an image) is covered with the background color when edited. Room for additional lines is only made in pasted images; on full scanned pages (e.g. a scanned invoice with a table), longer text runs over the text below, because table lines in the image cannot move along. On full scanned pages, dragging moves individual paragraphs, not the image. A paragraph is only formed when the line break is certain (the next line starts with a lowercase letter, or the column has a confirmed text width); a short paragraph on its own whose lines all start with a capital letter stays as separate lines. |
| Skewed scans | "Straighten page" only corrects the rotation; for pages photographed at an angle (keystone) use "Straighten photo (perspective)". Pages rotated by 90 or 180 degrees and skew above 12 degrees are not detected automatically (by hand up to 15 degrees). When straightening, the image of the page is recalculated and saved as JPEG at 150 to 300 dpi: the file can get larger (clearly so for black-and-white scans), and whatever is rotated beyond the page edge is lost; the corners that become free get the paper color. Form fields and comments stay in place and are slightly offset from the image afterwards. If text is changed in a skewed scan that has not been straightened, the new text is horizontal. Form field detection does not evaluate recognized text written at an angle (straighten the page first). |
| Text recognition | No text recognition is free of errors. In the tests with screenshots in seven fonts, 762 of 763 words were correct, all of them in the test invoice (scanned at 200 dpi), and all of the running text and the whole table in a recreated hotel invoice (skewed, blurry, noisy, split into strips). Lettering in logos (large, bold or gray text, text in emblems) is often not read or misread; recognition leaves out uncertain words instead of entering wrong ones. With very small, blurry or decorative fonts, individual letters can be confused (e.g. "rn" and "m"). So check briefly before passing documents on. |
| Export to Word/PowerPoint | Text, images and tables are transferred. Vector graphics are lost in editable mode. PowerPoint only creates tables in "editable" mode (in "exact" mode every slide is an image). |
| Tables in export | Detection works with rules; unusual layouts need rework. Merged cells are only detected in tables with lines. Cell background colors, line widths and line colors are not transferred (uniform gray border). A table across several pages becomes a separate table per page. If a table has only horizontal lines or only one column, the columns result from the text alignment. In tables without lines, a header row that spans several columns stays text above the table; if text of a cell extends into the neighboring column, the table ends there. Two-column running text is deliberately not treated as a table. Lines in nested objects of the PDF and tables on rotated pages are not detected. HTML, RTF and TXT still contain tables as text. |
| Export to Excel | Ambiguous notations: "1,250" is read as 1250, "1.250" as 1.25, "12.11" as the number 12.11. Anything starting with a zero (0041, 007), phone numbers, numbers with a hyphen and digit sequences longer than 15 digits stay text. Totals arrive as values; formulas are not recreated. In scanned tables every value depends on text recognition: double-check the numbers. |
| Detect form fields automatically | Detection works with rules and can miss fields or suggest too many; hence the preview. In scanned forms, radio buttons (circles) and dotted lines are not detected, and without prior text recognition the fields get no names from the labels. Straighten skewed scanned forms first. Rotated pages are not evaluated. Lines and boxes in nested objects of the PDF are not seen. Dropdowns, lists and comb fields (one box per letter) cannot be recognized by their look; comb fields are suggested as individual fields. A suggested name cannot be changed in the preview (deselect the field and create it by hand). Detected fields get no border of their own because the line or box is already on the page. |
| Appearance | The content of the PDF pages is never recolored (no night mode for pages). The menus, the window buttons and the Windows file dialogs are drawn by the system; the app switches them too, but their look was not measured in the automated test (only that the switch arrives). |
| Redact | Text in vertical writing under a mark stops the redaction (nothing is changed). Partly covered images that cannot be decoded and stored again (JPEG 2000, JBIG2, CCITT, images with a separate mask) are removed as a whole. Partly covered graphics that also clip other content lose their whole painting. Bookmark titles and attachment names that repeat the removed text are not changed (bookmarks are reported). Patterns are not looked into. |
| Digital signature | Only PFX/P12 files, no Windows certificate store, no timestamp. Only the first signature can certify a document. Self-created IDs show as "identity unverified". |
| Signed documents | Changes are appended and the signatures stay valid, but changes to the page content are reported as not permitted. Redacting, compressing or sanitizing writes the whole file again and invalidates the signatures (the app warns before saving). Existing comments are only visible there. Protected (encrypted) documents are always written again as a whole. |
| PDF/A | Checks the rules that can be decided from the objects; no certified validation (fonts' glyph widths, ICC profile contents, transparency groups in detail and PDF/A-1 are not checked). Fonts that are not embedded, DeviceCMYK without a CMYK profile and PostScript cannot be fixed automatically. |
| Formats and calculations | Only the standard format, validation and calculation scripts run without JavaScript; other scripts (e.g. a custom calculation) still need JavaScript to be allowed. Formats use English month and day names. A calculated field shows its plain value while it has the focus. |
| Accessibility | Automatic tagging uses the order of the page content as the reading order (check it in the Tags panel; tags cannot be moved there yet) and does not detect lists or tables. Text inside forms (nested objects) is marked as decoration. Comments are not tagged. Already tagged documents are not tagged again. Colour contrast and other rules that need a person are listed but not checked. |
| Batch OCR, scan clean-up | The review only covers words recognized since the document was opened. Clean-up does not change CMYK, indexed, JPEG 2000, JBIG2 or CCITT images, nor 16-bit images. A straightened photo replaces the page with the picture (the recognized text is read again); the corners are found only when the sheet's four edges are visible against a different background. |
| Action wizard | Steps have only the settings shown (watermark and header text, title); other settings use the defaults of the tools. Steps cannot ask for passwords (no protection step). JavaScript steps are not offered. |
| XFA forms | Scripts, calculations and validations of the form, images, rich text formatting, barcodes, rotated objects, column-spanning table cells and overflow leaders are not taken over. Text is set in Helvetica (Arial for characters it does not have). Splitting a single tall field across pages is not done. A form whose XFA part pdf-lib already removed (after an edit in an earlier version) can no longer be converted. |
| Preflight | Report on fonts, colors, transparency, page boxes. No profiles; the fixes are grayscale, hairlines and printer marks. |
| Grayscale, hairlines | Grayscale uses the device formulas, no ICC profile, so it is not calibrated for a press; Lab, indexed, Separation and DeviceN colours, patterns, shadings, inline images and 16-bit or indexed images stay in colour (the number of images left is reported). Hairlines in Type 3 fonts and tiling patterns are not fixed. A path that starts in one content stream and is stroked in the next is left as it is. |
| Header, footer, watermark | Marks added before version 1.2.0, or by other programs, are not recognised and cannot be updated or removed (except PdfCraft marks). Updating an image watermark asks for the image again. |
| Print layouts | No posters (tiling), no booklet creep, no cutting order for stacks. The pages are printed as images (as before). |
| Measure | Snapping reads the paths of the page content and its forms, not of comments; curves are approximated. Measurements are exported with the value and unit of their labels. |
| Recovery | Password-protected documents are not copied. Form values typed into a field that still has the focus may be missing from the copy. |
| Compress | CMYK, indexed and other colour spaces, images with colour-key masks or decode arrays and 16-bit images stay as they are. Greyscale images stored as JPEG become colour JPEGs. No JBIG2; pictures that a printer stored as many image strips are not merged. |
| Compare | Text differences only, no visual diff. |
| Third-party stamps | Are displayed but cannot be moved. Stamps are not part of the XFDF exchange. |
| Office to PDF | Best quality with Office installed. Without Office, only simple conversion of .docx, .xlsx, .csv. |

## Mac

DocPilot for Mac (macOS 12 or later, Apple silicon and Intel) has the same features as on Windows. The differences:

| Area | On a Mac |
|---|---|
| Keyboard | Shortcuts use ⌘ instead of Ctrl, and the interface shows them that way. macOS keeps ⌘H (hide), ⌘Tab (switch apps) and F11 for itself: reading mode is ⌃⌘H, the next and previous tab are ⌃Tab and ⌃⇧Tab, the full-screen window is ⌃⌘F. Redo also works with ⇧⌘Z. Preferences open with ⌘, as well as ⌘K. |
| Menu | The menu stays in the macOS menu bar at the top of the screen (there is no ☰ button); the DocPilot menu holds About, Preferences, Hide and Quit, as in other Mac apps. The three window buttons sit at the left of the title bar with the tabs. |
| Fonts | System fonts, fonts for all users and for the current user, and the fonts that come with Microsoft Office (e.g. Calibri). Office cloud fonts and the default font from Word's Normal template are not read, because macOS would ask for access to Office's data on every start; new text starts in Aptos 11 if installed, otherwise Calibri 11 or Arial. |
| Office to PDF | With Microsoft Office for Mac (Word, Excel, PowerPoint), if installed. The first time, macOS asks whether DocPilot may control the Office app and access its data. While macros are blocked, file types that can contain macros (.doc, .xls, .ppt, .docm, .xlsm, .pptm and similar) are not opened in Office. Excel for Mac can split a workbook whose sheets have different page setups into several PDFs; DocPilot then uses the first one. Without Office: the same simple conversion as on Windows. |
| Scanner | "PDF from scanner" opens the macOS scanner window (as in the Image Capture app); choose the scanner on the left and click "Scan". |
| Paste screenshots | ⌘V pastes a screenshot taken to the clipboard with ⌃⇧⌘4. |
| Appearance | "Same as macOS" follows System Settings > Appearance. |
| JavaScript and macros | Blocked, as on Windows. |
| First start | The app is signed, but not yet notarized by Apple: macOS asks once before the first start (see the README). |

## Deployment

Silent installation: `msiexec /i DocPilot-x64.msi /qn`

If DocPilot is open while installing, updating or uninstalling, the MSI stops with the message "DocPilot is still open ..." (error code 1603) before anything is changed. Otherwise Windows would only replace program files on the next restart, which can damage the installation. When deploying with Intune or SCCM, the installation is simply retried later.

The MSI is not digitally signed. Without a code signing certificate, Windows shows warnings or AppLocker may block it. PDF is registered as a file type. Windows does not allow an installer to set the default app; choose DocPilot as the default PDF app in the Windows settings.

For updates, increase the version in `package.json` and run `npm run dist`. The new MSI then replaces the old version.

## JavaScript and macros

JavaScript in PDF documents and macros when converting Office files are **blocked**. The options for them in Preferences are switched off. Scripts in documents are never run, and Office files are converted without running their macros.
